# Сверка требований ТЗ с реализацией

Требования ТЗ и уточнения организаторов, сопоставленные с реализацией. Все экраны обоих кабинетов
проверены в браузере (Playwright) на ширине 1280 и 375 px. Обозначения: ✅ готово, 🟡 частично.
Подробное описание решений находится в `docs/architecture.md`.

## 7. Решения по спорным пунктам

1. Ожидания кандидата по зарплате скрыты от работодателя и работают как скрытый порог. Они убраны
   из `CandidateEmployerView`, текст согласия `PROFILE_PUBLICATION` обновлён до версии 2026-10-06,
   поэтому опубликованные кандидаты подтверждают его заново.
2. Свободный текст профиля («о себе», должность и описание опыта, образование, город, свои навыки)
   уходит работодателю через `mask_contacts` (`backend/app/schemas/candidates.py`): email, телефон,
   ссылки, @ник и «tg: ник» заменяются на «[контакт скрыт]», пока доступ к контактам не открыт. Это
   эвристика: запись «иван собака мейл ру» она не поймает, а декоратор `@retry` скроет. Кандидат
   видит результат в предпросмотре, форма предупреждает об этом. Тесты:
   `backend/tests/test_mask_contacts.py`.
3. Специализация категории фиксируется при старте теста (`candidate_grades.specialization_id`),
   необязательная специализация в профиле на категорию не влияет.
4. ФСП ID подключён не как Identity Provider realm `fsp`, а отдельным OIDC-клиентом к realm `fsp-id`
   (`backend/app/services/fsp.py`). Если вход через ФСП ID станет обязательным, он добавляется в
   realm `fsp` как Identity Provider без изменений бэкенда (архитектура §4.1).
5. Переписка после отзыва доступа к контактам доступна только для чтения: история видна обеим
   сторонам, новое сообщение даёт 409 `ChatClosedError`. Переписка тоже способ связи, и отзыв должен
   прекращать контакт; снова открыть её может только принятие нового приглашения компании.

### Рассмотренные альтернативы

| Вариант | Почему отклонён | Решение |
|---|---|---|
| Веса соревнований по уровню (Чемпионат России 1.0, регион 0.4, участие 0.15) | Организаторы попросили считать все соревнования равными и учитывать результаты, а не участие | Равные веса, учитываются только призовые результаты и финалы |
| Локальные LLM (Ollama) | Разрешены только российские модели, GPU на сервере проверки нет | GigaChat или YandexGPT по API с запасным вариантом без LLM (путь развития) |
| Песочница для исполнения кода (Judge0) | Не требуется, задания проверяются без исполнения кода кандидата | Не используется |
| Автопонижение грейда по порогу после провала | ТЗ запрещает понижать грейд принудительно | Предлагается тест на G−1, если θ в его диапазоне |
| Redis, воркеры, outbox, S3 | Не нужны при нагрузке в десятки пользователей | Истечение считается при чтении, файлы в volume за интерфейсом `FileStorage` |
