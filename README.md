# ФСП Карьера

Платформа подбора ИТ-специалистов с обратной механикой. Кандидат проходит тест и получает
категорию «направление × грейд». Работодатель описывает потребность, получает подборку с
объяснением и сам приглашает кандидата, указывая вилку зарплаты. Контакты кандидата открываются
компании, только когда он принял приглашение.

Решение задачи специального трека ФСП хакатона «Лидеры цифровой трансформации 2026».

## Состав

```
gateway (nginx) ─┬─ frontend   React, TypeScript, Vite, shadcn/ui
                 ├─ backend    FastAPI, SQLAlchemy, Alembic: данные, права, сценарии
                 ├─ keycloak   вход, регистрация, подтверждение email
                 └─ mailpit    перехват писем (/mail)
backend ──► scoring   FastAPI без состояния: банк заданий, IRT, ранжирование
backend ──► postgres  PostgreSQL 17 (+pgvector)
```

## Запуск

Нужны Docker и Docker Compose.

```sh
cp .env.example .env          # поменяйте пароли и секреты
docker compose up -d --build  # миграции применяются при старте backend
```

Приложение откроется на `http://localhost:8080` (порт задаёт `GATEWAY_PORT`). Письма с
подтверждением email приходят в `/mail` (логин и пароль в `MAILPIT_UI_AUTH`).

Демо-кандидаты для подборки: 90 человек, которые проходят настоящий тест
(`docs/architecture.md`, §5.3).

```sh
docker compose exec backend python -m app.demo_seed
```

Демо-режим для жюри: `DEMO_MODE=true` в `.env` включает быстрый вход кандидатом или работодателем
без регистрации (песочница живёт сутки) и экспресс-тест из 6 заданий. Полный путь с регистрацией
тоже работает. Зарегистрированные пользователи песочниц не видят, а песочницы видят друг друга
ниже засеянных кандидатов и вакансий.

ФСП ID на стенде тестовый (mock-реалм Keycloak). В профиле кандидата есть кнопка «Привязать ФСП ID»,
логины `athlete1`-`athlete4`, пароль `fsp-demo`. У athlete1 победы, призовые места и звание КМС, у
athlete2 финал и I разряд, у athlete3 только участие (в подборке не засчитывается), у athlete4
истории нет. Спортсмена, привязанного к песочнице, может привязать следующий проверяющий.

## Сценарий для жюри

Быстрее всего начать с демо-входа на главной (нужны `DEMO_MODE=true` и запущенный `demo_seed`).
Кандидат и работодатель живут в разных песочницах, поэтому вторую роль удобно открыть в окне
инкогнито. Номер своей песочницы-кандидата виден на вкладке «Как вас видят работодатели», в подборке
работодателя песочницы стоят в конце списка. Письма стенда приходят в `/mail`.

Кандидат (кнопка «Войти как демо-кандидат»):

1. Профиль уже заполнен. «Заполнить из резюме» принимает PDF и подставляет контакты, навыки, места
   работы и стаж в пустые поля. В «Видимости» можно скрыть разделы до принятия приглашения, в
   «ФСП ID» дать согласие на данные реестра и привязать тестовый ФСП ID (`athlete1`, пароль
   `fsp-demo`).
2. «Категория и тест»: выберите грейд, экспресс-тест из 6 заданий включён по умолчанию. Каждый
   получает свои экземпляры заданий одной сложности, у порога грейда тест добавляет задания. В
   результате видны итоги по компетенциям и устойчивость результата. С привязанным ФСП ID появится
   подсказка грейда.
3. «Приглашения»: уже есть приглашение от «Пример Технологии» с вилкой, блоком «почему вам», кейсом
   и репутацией компании. «Принять» открывает компании контакты, названия мест работы и переписку,
   доступ можно закрыть. Вместо отказа по зарплате можно ответить «готов при вилке от X», и компания
   поднимет вилку одним действием. Здесь же можно пожаловаться на компанию.
4. «Вакансии»: лента вашего направления с процентом совпадения. «Откликнуться» сразу открывает
   компании профиль (без подтверждённого грейда не больше 3 откликов в неделю).
5. «Кейс недели» и «Как вас видят работодатели»: обезличенный профиль и «Скачать PDF».

Работодатель (кнопка «Войти как демо-работодатель»):

1. «Потребности»: готовая потребность «Python-разработчик», опубликованная как вакансия. На неё уже
   откликнулись два демо-кандидата (блок «Отклики на вакансию» внизу страницы потребности).
2. «Кандидаты»: подборка по потребности с категориями «направление × грейд», объяснением позиции,
   вкладом каждого фактора, фильтрами и шортлистом. Карточка кандидата показывается без ФИО и
   контактов, с паспортом навыков («подтверждён тестом», «заявлен», «нет»), результатами и разрядом
   ФСП из реестра, её можно скачать в PDF. Отсюда же отправляется приглашение с вилкой и кейсом.
3. «Приглашения»: статусы, ответы кандидатов, встречные предложения («Поднять вилку до X»), отклики
   («пригласить к разговору» или отказ), переписка после принятия.
4. «Компания»: уровень доверия и квота приглашений, подтверждение домена письмом на адрес в домене
   сайта компании (письмо придёт в `/mail`), токен для ATS и лента событий `GET /api/v1/ats/events`.

Полный путь без демо-режима:

1. Зарегистрируйтесь кандидатом (письмо с подтверждением придёт в `/mail`), заполните профиль и
   пройдите тест в «Категория и тест».
2. В другом браузере зарегистрируйтесь работодателем, создайте компанию и потребность, откройте
   подборку и отправьте кандидату приглашение.
3. Кандидатом примите приглашение во вкладке «Приглашения»: компании откроются контакты и переписка.

Админка находится в `/admin` (`ADMIN_USERNAME` / `ADMIN_PASSWORD`): справочники, реестр ФСП, жалобы
на компании.

## Разработка

```sh
# backend (нужен Postgres: docker compose up -d postgres, порт в POSTGRES_PORT)
cd backend && uv sync && uv run alembic upgrade head
uv run uvicorn app.main:create_app --factory --reload
uv run pytest && uv run ruff check . && uv run mypy app migrations
uv run python -m validation.resume              # пишет docs/validation-resume.md

# scoring
cd scoring && uv sync && uv run uvicorn app.main:create_app --factory --port 8001 --reload
uv run pytest && uv run ruff check . && uv run mypy app
uv run python -m validation.assessment > ../docs/validation-assessment.md
uv run python -m validation.matching > ../docs/validation-matching.md

# frontend (API через прокси на gateway, см. vite.config.ts)
cd frontend && pnpm install && pnpm dev
pnpm typecheck && pnpm lint && pnpm format:check
pnpm api:generate   # клиент API из OpenAPI бэкенда
```

Версии библиотек зафиксированы в `backend/uv.lock`, `scoring/uv.lock`, `frontend/pnpm-lock.yaml`.
